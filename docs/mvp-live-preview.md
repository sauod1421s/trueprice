# TruePrice — نسخة MVP التجريبية المحلية (فرع `mvp-live-preview`)

نسخة كاملة من موقع TruePrice الحالي (نفس التصميم والصفحات والروابط والسيارات والبحث)، مربوطة بقاعدة
PostgreSQL **تعمل على جهازك فقط**، وجاهزة للربط بـ Supabase بعد الموافقة. لا Vercel، لا مفاتيح سرية في Git.

## التشغيل (أول مرة)

المتطلبات: Node.js 22 وnpm، واتصال إنترنت لتثبيت الحزم وخطوط Google فقط. القاعدة نفسها تُحمَّل كحزمة npm
(`embedded-postgres`) لأنظمة macOS وWindows وLinux، فلا حاجة لتثبيت PostgreSQL.

```bash
git fetch origin
git checkout mvp-live-preview
npm ci
npm run mvp:setup     # ينشئ القاعدة في .local/ ويطبّق المخطط وينقل الكتالوج الحالي (52 منتجًا)
npm run mvp:dev       # يشغّل القاعدة + الموقع
```

ثم افتح:

- الموقع: <http://localhost:3000>
- لوحة الإدارة: <http://localhost:3000/admin> (اختر أحد مستخدمي الاختبار: «مشرف تجريبي أ» أو «ب» أو «مراجع تجريبي»)

أوامر أخرى:

| الأمر | ما يفعله |
| --- | --- |
| `npm run mvp:dev -- -p 3001` | نفس التشغيل على منفذ آخر |
| `npm run mvp:build` ثم `npm run mvp:start` | نسخة إنتاجية محلية (أسرع) |
| `npm run mvp:reset` | حذف القاعدة المحلية وإعادة إنشائها من الصفر |
| `npm run dev` | الموقع بوضعه العادي تمامًا (من ملفات `app/data`، بلا قاعدة) |

كل ما يُولَّد محليًا (بيانات القاعدة، كلمات المرور، سر جلسة المعاينة) في مجلد `.local/` المستبعد من Git.
القاعدة تستمع على `127.0.0.1:54329` فقط.

## الوضعان

- **الوضع العادي** (الافتراضي، وهو ما على الموقع المنشور): لم يتغيّر شيء. فُحصت 64 صفحة ورابطًا مقابل نسخة
  `phase-1-release-candidate` وكانت متطابقة (النص، العناوين، canonical، RTL، الوصف، sitemap، robots).
- **وضع MVP** (`TP_DATA_SOURCE=db`، تضبطه أوامر `mvp:*` تلقائيًا): المنتجات والتصنيفات والمتاجر والأسعار من القاعدة.

## تجربة دورة العمل يدويًا

1. ادخل «مشرف تجريبي أ» ← **المنتجات**: أضف منتجًا (ضع علامة «بيانات تجريبية»).
2. **المتاجر والمصادر**: أضف متجرًا (أو أكثر) ومصدر سعر.
3. **استيراد الأسعار**: الصق CSV بالريال (`product_id,store_id,price,currency,url`) أو أدخل سعرًا واحدًا.
4. صفحة **المعاينة** تعرض الصفوف والسعر الحالي لكل عرض. لا يظهر شيء في الموقع قبل الاعتماد.
5. اضغط «اعتماد الاستيراد»، فتذهب الأسعار للمراجعة.
6. اخرج وادخل «مراجع تجريبي» ← **مراجعة الأسعار**: اعتمد أو ارفض (من استورد لا يستطيع اعتماد سعره).
7. افتح صفحة المنتج: الأسعار المعتمدة، الأقل/المتوسط/الأعلى، السعر العادل (عند وجود 3 متاجر موثقة)، وسجل الأسعار.

الرقم العام للمنتج الجديد = 900000 + رقمه في القاعدة (لا يتصادم مع أرقام المنتجات الحالية `legacy_id`).

### ملفات الشركاء (CSV · Google Merchant · YML · XML)

1. **المنتجات** ← «باركود أو رقم موديل لمنتج»: أضف الباركود (GTIN) أو رقم الموديل (MPN) من علبة المنتج أو صفحته الرسمية.
2. **المتاجر والمصادر** ← مصدر من نوع «ملف متجر واحد» مرتبط بالمتجر، مع أساس الإذن.
3. **استيراد الأسعار** ← «ملف شريك»: يُحلَّل الملف على الخادم، ويُرفع فقط الصف المطابق **بالباركود أو رقم الموديل**،
   بالريال، وحالته جديد، ومتجره نشط. الباقي (تشابه بالاسم، متجر غير معروف، عملة أخرى، مستعمل، صف غير صالح)
   يظهر في المعاينة تحت «صفوف لم تُرفع» مع السبب، ولا يُدمج تلقائيًا أبدًا.
4. السعر الذي لا يذكر الملف تاريخه يُعلَّم «تاريخ غير مؤكد» فلا يدخل السعر العادل.
5. بعدها نفس الدورة: اعتماد الاستيراد ← مراجعة من شخص آخر ← الظهور.

إدارة أخرى من اللوحة: إخفاء منتج من الموقع وإعادته (لا حذف، والسجل محفوظ)، إيقاف مصدر مؤقتًا (لا يقبل
استيرادًا جديدًا) وإعادة اعتماده، ومنح الأدوار وسحبها من **المستخدمون**.

### السيارات

نُقلت السيارات (357 موديلًا من 40 علامة) وأسعارها المرجعية (75) إلى القاعدة كأسعار غير موثقة. صفحة العلامة
بوضع القاعدة تعرض فوق المرجع القديم قسم «سعر معتمد من مراجع» لكل موديل له سعر اعتمده مراجع (من `pub.new_car_offers`).
بالوضع العادي الصفحة كما هي تمامًا.

## ما عُطّل مؤقتًا (دون حذف) وكيف يُعاد

| الميزة | الحالة في MVP | الإعادة |
| --- | --- | --- |
| تحويل العملات | الاستيراد يقبل الريال فقط؛ دوال سعر الصرف غير متاحة للوحة | `db/mvp/restore_disabled_features.sql` (أ، ب) |
| الاستيراد الآلي (خدمة ingest) | الاستيراد من لوحة الإدارة فقط | نفس الملف (ج) |
| الاستيراد الضخم | حد 1,000 صف للتشغيل الواحد (الأصلي 20,000 محفوظ) | نفس الملف (د) |
| مطابقة ملفات الشبكات بالاسم | لا تُدمج تلقائيًا؛ تظهر كملاحظة لإضافة الباركود الصحيح (معاينة المرحلة 1 باقية في `/admin/import`) | — |
| مصادر آلية (شبكات تسويق، واجهات رسمية) | الجداول والدوال جاهزة (`ingest_api`، دور `ingest_service`)؛ التنفيذ مغلق | (ج) بعد: إذن مكتوب من المصدر + `allow_automated` للمصدر + كلمة مرور للدور خارج Git |

الجداول والدوال والتصميم باقية كلها؛ ملف الإعادة لا يُنفَّذ تلقائيًا.

## الأسعار المرجعية القديمة

أسعار `app/data/products.ts` الحالية نُقلت عبر مسار الاستيراد نفسه، وبقيت **غير موثقة وتاريخها غير مؤكد**.
لا تدخل في أي حساب، وتُعرض في قسم منفصل موسوم «أسعار مرجعية قديمة غير معتمدة»، كما في الموقع الحالي.
لإخفائها تمامًا (تطبيق «لا عرض قبل الاعتماد» حرفيًا):

```bash
TP_SHOW_LEGACY_REFERENCE=off npm run mvp:dev
```

## الرجوع

- الموقع العادي: `npm run dev` على نفس الفرع، أو `git checkout phase-1-release-candidate`.
- إزالة القاعدة المحلية: احذف مجلد `.local/`.
- كل خطوة كبيرة في سجل Git كمرحلة مستقلة (`git log --oneline phase-1-release-candidate..mvp-live-preview`).

## الدخول للوحة

- **محليًا:** دخول تجريبي باختيار مستخدم اختبار (يعمل فقط مع قاعدة محلية، ويُعطَّل تلقائيًا على Vercel).
- **مع Supabase:** بريد + كلمة مرور + تحقق ثنائي TOTP إلزامي (Supabase Auth)، والهوية لا تُقبل على الخادم إلا
  بعد التحقق من توقيع الرمز (`getClaims`). الإعداد: `docs/supabase-setup-ar.md`، وخطة القاعدة:
  `docs/supabase-production-plan.md` (بانتظار الموافقة). المتغيرات: `.env.example`.

## ليس في هذه النسخة

- لم يُنفَّذ أي SQL على Supabase بعد، ولم يُختبر الدخول عبر مشروع Supabase حقيقي (اختُبر مسار التحقق من التوقيع
  بمفاتيح اختبار محلية).
- لا يُنشر شيء على Vercel من هذا الفرع (`vercel.json`).
