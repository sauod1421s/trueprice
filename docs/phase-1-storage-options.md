# المرحلة 1 — قرار التخزين الدائم (بانتظار اعتماد المالك)

## لماذا توقفنا هنا

الموصّل الحالي يعمل بدون تخزين: يقرأ الملف، يتحقق، يطابق، ويعرض النتيجة
للمعاينة. لكن البنود التالية تحتاج حفظًا دائمًا على الخادم، والمشروع اليوم
لا يملك قاعدة بيانات ولا نظام دخول:

- قائمة مصادر البيانات وحالة كل مصدر وآخر تحديث له.
- سجل الأسعار الإلحاقي (لا يُستبدل ولا يُحذف).
- قرارات المراجعة اليدوية للمطابقة وأحداث التحقق (موثق / مرفوض).
- سجل عمليات الاستيراد والأخطاء.
- تشغيل الاستيراد المجدول من روابط الملفات (يحتاج مكانًا يُحفظ فيه الناتج).
- نظام دخول للمشرفين قبل السماح بأي كتابة.

## الخيارات

| الخيار | ما يوفره | التكلفة التقريبية | ملاحظات |
|---|---|---|---|
| **أ) Supabase (PostgreSQL)** — الاتجاه المعتمد مبدئيًا سابقًا | قاعدة بيانات + دخول للمشرفين + تخزين ملفات في خدمة واحدة | المجاني: 0$ (قاعدة 500MB، يتوقف بعد أسبوع بلا نشاط). Pro: ‏25$ شهريًا كأساس (8GB) + استخدام إضافي | الخطة المجانية مناسبة للتجربة فقط بسبب التوقف التلقائي |
| **ب) قاعدة PostgreSQL أخرى عبر Vercel Marketplace (مثل Neon)** | قاعدة بيانات فقط | خطط مجانية ومدفوعة حسب الاستخدام | يحتاج حلًا منفصلًا لدخول المشرفين |
| **ج) ملفات في GitHub (بدون قاعدة بيانات)** | حفظ ناتج الاستيراد كملفات JSON في المستودع عبر طلبات دمج | 0$ | لا يناسب سجل أسعار متنامٍ ولا لوحة إدارة تكتب مباشرة؛ مقبول كحل مؤقت جدًا |

## ما نحتاجه منك

1. اختيار الخيار (أ / ب / ج).
2. الموافقة على التكلفة إن كانت مدفوعة.
3. الموافقة على بنية الجداول المقترحة قبل إنشائها:
   `sources`، `imports`، `import_issues`، `price_observations` (إلحاقي)،
   `verification_events` (إلحاقي)، `product_identifiers` (باركود/موديل لكل منتج)،
   `match_decisions`، `admin_users`.
4. أخذ نسخة احتياطية كاملة قبل أي ترحيل للبيانات الحالية (حسب قواعد العمل).

لن يُنشأ أي حساب أو خدمة أو ترحيل قبل موافقتك الصريحة.
